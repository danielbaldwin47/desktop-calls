Legend: **[V]** = verified (where is stated). **[I]** = inferred, not tested.

**Bottom line:** pinning lives in the tray's own popup, which opens on a right-click of its arrow; step 7.3 now says so. Opened from the Indicator, the Dialer logged no `activate-requested`, so 7.4 had nothing to measure; every way of opening it now logs one. The app cannot stop Hyprland's Super+W from closing the window behind the Dialer on its own. A user bind (proposal below) plus the Dialer's new Super+W handling closes the Dialer and nothing else.

## 1. Pinning a tray item in Omarchy 4.5

- Right-clicking the tray's arrow (the expand icon) opens the "Tray icons" popup (/usr/share/omarchy/shell/plugins/bar/widgets/Tray.qml:296-297). Each row there has a pin button (Tray.qml:535-546), labelled "Pin" or "Unpin" (/usr/share/omarchy/default/i18n/en/shell.json:509, :513). **[V]** (source)
- Right-clicking an item opens that item's own menu (Tray.qml:909-917). That is what the user saw. **[V]** (source, and the user's sitting)
- Items are matched by their StatusNotifierItem `Id` (Tray.qml:183-186). Desktop Calls' `Id` is `desktop-calls` (crates/desktop-calls/src/indicator.rs:283-285). The click saves the pin to `~/.config/omarchy/shell.json` itself, so the step never asks the user to edit that file. **[V]** (source)
- Step 7.3 now reads: right-click the small arrow at the tray end of the bar, not the phone icon; in Tray icons, click Pin on the Desktop Calls row.

## 3. Super+W with the Dialer open

What happens in Hyprland 0.56.2, verified in source **[V]**:

- Omarchy binds Super+W, and Super+Q, to Close window (/usr/share/omarchy/default/hypr/bindings/tiling.lua:1-2).
- Keybinds run whatever surface has keyboard focus (src/managers/KeybindManager.cpp:348-409).
- Close window acts on the focused window, `Desktop::focusState()->window()` (src/config/shared/actions/ConfigActions.cpp:47-49, 139-147). A layer surface taking the keyboard changes only the focused surface, not the focused window (src/desktop/state/FocusState.cpp:223-270, 298-300). So the terminal behind the Dialer closed.
- No layer rule or keyboard mode changes this. Hyprland never closes a layer surface on request; it calls `sendClosed` only when a monitor goes away (src/output/Monitor.cpp:455).

What the app can do alone, and why it doesn't:

- **Keyboard-shortcuts-inhibit:** Hyprland honours it for layer surfaces (src/protocols/ShortcutsInhibit.cpp:48-86). But while the Dialer had the keyboard it would block every bind, Super+Space and the workspace keys included, so it is not used. **[I]** whether GTK 4 can inhibit from a gtk4-layer-shell window.
- **Becoming an xdg toplevel:** Close window would then send the Dialer `close` (src/desktop/view/Window.cpp:2947-2950). But it would lose the overlay layer, its placement, and its keyboard grab. Not done.

What this PR does: Super+W in any of the app's surfaces now does what Escape does. In the Dialer, that closes it without calling anyone (crates/desktop-calls/src/surfaces.rs, `is_escape`). The scenario `super_w_closes_the_dialer_as_escape_does` passes. **[V]** (headless sway, which binds no keys, so Super+W reaches the Dialer)

### Proposal: one bind in the user's Hyprland config (not applied)

Add this to `~/.config/hypr/bindings.lua`. Omarchy loads that file after its defaults (~/.config/hypr/hyprland.lua:14-21), and `o.rebind` unbinds the default first (/usr/share/omarchy/default/hypr/helpers.lua:155-158).

```lua
-- Desktop Calls: with its Dialer open, Super+W closes the Dialer, not the window behind it.
o.rebind("SUPER + W", "Close window", function()
  for _, layer in ipairs(hl.get_layers({ namespace = "desktop-calls-dialer" })) do
    if layer.mapped and layer.interactivity == 1 then return { pass_event = true } end
  end
  hl.dispatch(hl.dsp.window.close())
end)
```

- `hl.get_layers` filters by namespace (src/config/lua/bindings/LuaBindingsQuery.cpp:343-366). Layers expose `mapped` and `interactivity` (LuaLayerSurface.cpp:56-71). The Dialer's namespace is `desktop-calls-dialer` (crates/desktop-calls/src/surfaces.rs:384). **[V]** (source)
- `{ pass_event = true }` sends the key on to the focused surface (LuaBindingsRegistration.cpp:30-38, 64-84; KeybindManager.cpp:835-842). **[V]** (source)
- **[I]** that `interactivity == 1` means exclusive (the wlr enum), and that the bind works as written. Not run on any Hyprland.
- Super+Q needs the same lines if the user wants it covered too.
- `just install` could offer this bind later, asking first. It must never write it unasked.
