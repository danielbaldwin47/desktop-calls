# Omarchy 4.5 re-check of shell integration — 2026-11-04

omarchy 4.5.0-2 (upgraded from 4.0.6-1 today) · Hyprland 0.56.2 · quickshell 0.3.2 · gtk4 4.24.1 · libadwaita 1.10.0. Read-only. S = /usr/share/omarchy/shell, N = S/plugins/notifications. The 4.0.6 tree was diffed from the cached package /var/cache/pacman/pkg/omarchy-4.0.6-1-x86_64.pkg.tar.zst. Supersedes parts of [the 4.0.6 note](2026-11-04-omarchy-shell-integration.md).

## Sources for "what changed"
- No changelog ships in the package, and /usr/share/omarchy is not a git checkout. Upstream (github.com/omacom/omarchy, also reachable as basecamp/omarchy) has no final v4.5.0 release, only v4.5.0-rc1 to rc3. The rc3 notes say notifications were "rebuilt" (engine from Omapager, N/Service.qml:4-5): "Action buttons … work right from the card", stacking by sender, DND moved to the bar bell and `Super+Ctrl+Alt+Comma`, `Super+Comma` now acts on the newest card. They also note "Allow bar widgets to live in the tray's drawer" (#15281) and a new Appearance menu. I found nothing in the notes about GTK or libadwaita theming.
- N was rewritten: NotificationLogic.js and components/ are gone. It is now Service.qml plus Delivery/Store/Detect/Markup/Security/Layout/Icons.js, Toast.qml and DeedButton.qml.

## 4.0.6 findings, re-checked
1. **Tray watcher: unchanged.** Verified: `busctl --user list` shows `org.kde.StatusNotifierWatcher` and the Host, owned by quickshell PID 482909. `omarchy.tray` is still in the user's layout (~/.config/omarchy/shell.json:60) and in the default (/usr/share/omarchy/config/omarchy/shell.json:45). Passive items are still skipped (S/plugins/bar/widgets/Tray.qml:199). Unpinned items still go to the drawer (Tray.qml:22-27). Left click calls `activate()` unless the item is `onlyMenu`, middle click calls `secondaryActivate`, right click opens the menu (Tray.qml:909-917). New: the layout has a `tray` section, so bar widgets can live in the drawer (TrayModel.js:22). Not new, but missed in 4.0.6: NeedsAttention is drawn exactly like Active ("attention" appears 0 times in Tray.qml), so the ringing state must show through the icon itself.
2. **Bar plugins: unchanged in substance.** Plugins are still discovered from `~/.config/omarchy/plugins/<id>/` (S/services/PluginRegistry.qml:11). `rescanPlugins` is at S/shell.qml:1796. The `omarchy plugin` commands are the same set as 4.0.6, including `validate`. Only first-party manifests get capabilities (PluginRegistry.qml:92-93), so third-party plugins still run as plain QML in the shell. **Wrong now:** the 4.0.6 citation "S/README.md:46-141". That README is now 9 lines and links to docs/omarchy-shell.md, which the package does not ship.
3. **DND reading: the path changed.** Verified: `omarchy-shell notifications isDnd` returns `off` (N/Service.qml:1402; toggleDnd/setDnd at :1404-1413). **`dndState` was removed**; it now returns "Function not found". **The 4.0.6 state file `~/.local/state/omarchy/notifications.json` is deleted** by migration /usr/share/omarchy/migrations/1792648436.sh:15. DND now lives in `~/.local/state/omarchy/notifications/quiet.json` as `{"dnd":true|false}` (Service.qml:1165-1169, :1248; Store.js:265-276). The directory is mode 0700. The file can be **0 bytes**, which means off; it is 0 bytes on this machine now. It is written with an atomic rename about 250 ms after a change (Service.qml:1229-1233, :1304-1308). A watcher must therefore watch the directory, not the file inode. The shell only reads it at startup, so this file is read-only for us.
4. **DND bypass: one new rule.** Still bypassing: app_name `omarchy-action`, or `notify-send` with urgency critical (N/Delivery.js:11-15). `critical` from any other app is still silenced. **New:** any notification in which Detect.js finds a "verification code" also bypasses DND (Delivery.js:43-49). A code is a run of 4-8 digits within about 24 characters before or 72 after a keyword such as code, pin, verify, confirm or otp (Detect.js:8-19). The card then also gets a "copy code" button. Missed-Call text must avoid those words near the number, and a Contact named "Pin" could trip it (inferred). Silenced notifications still go to history unless `transient` is set (Service.qml:601-604, Delivery.js:37-41).
5. **Action buttons: now drawn, so the 4.0.6 claim is wrong.** `GetCapabilities` is unchanged (verified: `persistence body body-markup body-hyperlinks actions icon-static`, `actionsSupported: true` at Service.qml:1357). Sender actions become buttons (Delivery.js:21-33, Toast.qml:527-557), up to 3 per row and 16 in all (Security.js:5). Caveats: an action with id `default` is never drawn because the card click runs it, and an action labelled "Settings" is hidden (Service.qml:896-902). Buttons show only on the front card of a stack, or on the hovered card when the stack is expanded (Toast.qml:532). Number keys press them in keyboard mode (Service.qml:405-409). A pressed button closes the card (Service.qml:908-912).
6. **Click behaviour: the same order as before.** First an Omarchy `--exec` command, then the sender's `default` action, then the sender's window, then its site (Service.qml:1071-1097). `Super+Comma` on a card with a default action and one button has two choices, so it hands over the keyboard instead of acting (Service.qml:859-864).
7. **Toast geometry: changed.** The namespace is still `omarchy-notifications` on the Overlay layer. It is no longer a full-screen surface (the old anchors were all four sides). It is now a constant-width column anchored top, bottom and right (Service.qml:1515-1523). The column ignores exclusive zones, and its input mask covers only the cards (:1519, :1525). Card width is `Style.space(380)` (:77). Margins are the bar thickness plus gapsOut on the bar's edge (Delivery.js:88-97). Verified with `hyprctl layers`: on DP-3 (2400×1350 logical), `omarchy-notifications` is at x 2006, width 394, full height. The deck opens on the focused output and stays there until it empties (Service.qml:31-45). The column is unmapped under a real fullscreen window until a card arrives, because any overlay surface blocks Hyprland direct scanout (Service.qml:80-85, :1510-1512).
8. **Bar: the conclusion stands, the evidence changed.** `omarchy-bar` is now a full-screen top-layer surface, 2400×1350 in `hyprctl layers`, so the 4.0.6 "26px surface" no longer holds. It still claims exclusiveZone = thickness (S/plugins/bar/Bar.qml:1726-1727, :1795-1798). Verified: `hyprctl monitors` reports reserved `[0, 26, 0, 0]`. New: an `omarchy-dock` layer at the bottom on floating workspaces. There are still no layer rules for custom namespaces (/usr/share/omarchy/default/hypr/apps/omarchy-shell.lua:5,12,17).

## Consequences for spec #1 (inferred)
- Banner: anchor top-right with the default exclusive zone, so it sits below the bar. Set the right margin to at least the width of the `omarchy-notifications` layer (394 here; read it from `hyprctl layers -j`, falling back to about 400) plus a gap. Keep the Banner unmapped when nothing is ringing, so it does not break direct scanout. Under DND the Banner is still required, because a toast would be silenced.
- Missed Calls: "Call back" (#78) is now drawn on Omarchy. Spec line 24, "Omarchy never draws those", is out of date. Repeat Calls should keep using `replaces_id`, which updates the card in place (Service.qml:579-580). Cards group under `app:<slug of app_name>` (Markup.js:141-147).
- DND adapter and harness stand-in: switch to `notifications/quiet.json`, treat missing, empty or invalid as off, and watch the directory.

## Theming
- Omarchy's own Qt apps (omarchy-app skill) use Material Dark with only the theme `accent`. They read it from `~/.local/state/omarchy/current/theme/colors.toml` and get rounding from `hyprctl getoption decoration:rounding`. They do not use the full palette.
- What Omarchy sets for GTK: `omarchy-theme-set-gnome:20-34` sets the gsettings `color-scheme` (prefer-dark or prefer-light, from `mode` in colors.toml), `gtk-theme` (Adwaita or Adwaita-dark) and `icon-theme`. It runs from omarchy-theme-set:545 and is identical to 4.0.6. Verified: the portal reports color-scheme 1, but accent-color "Requested setting not found". gsettings `accent-color` is the default `'blue'`. Omarchy does **not** set the accent, the font (gsettings has 'Adwaita Sans 11'; the shell uses the fontconfig `monospace` alias, S/Commons/Style.qml:267-271) or any gtk.css colours. Glass mode only imports a blur (omarchy-theme-set-glass:112-121), and there is no GTK template in default/themed/.
- Change signal: a switch runs `rm -rf current/theme` then `mv` of the new directory into place (omarchy-theme-set:494-495). It then writes `current/theme.generation` (:500-501) and `theme.name` (:506), then gsettings. Watch `~/.local/state/omarchy/current/` with a GFileMonitor, debounce, and re-read `theme/colors.toml` (flat `key = "#rrggbb"` pairs: accent, background, foreground, the ANSI colours, `mode`). For toast-like chrome, also read `theme/shell.toml` (for example `[hyprland] active-border`).
- Best GTK4/libadwaita route: light/dark follows live for free through AdwStyleManager and the portal. For the palette, generate a GtkCssProvider at APPLICATION priority that overrides libadwaita's CSS variables (`--accent-bg-color`, `--accent-color`, `--window-bg-color`/`-fg-color`, `--view-*`, `--card-*`, `--headerbar-*`, `--popover-*`) from colors.toml. Swap the provider on change, and set the radius from Hyprland rounding. Fall back to stock Adwaita without Omarchy.
- Match quality: with that provider, a libadwaita window matches colour, accent and corners at least as well as Hype or Monologue, which take only the accent. Remaining gaps are Adwaita's widget shapes and its sans font against the shell's monospace font. A standalone Qt Quick app would **not** match materially better, because it gets neither the shell's palette nor qs.Ui for free. Only a QML plugin running inside omarchy-shell would match exactly, and that would be Omarchy-only. ADR 0003 stands.
