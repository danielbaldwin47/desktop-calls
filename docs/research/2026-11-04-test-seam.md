# Test seam: the app on GLib, the Simulated Phone and the harness

Date: 2026-11-04. Ticket #4. Desktop and stack as in the [first Phone connection note](2026-11-04-first-phone-connection.md); Phone shapes from the [D-Bus snapshot](2026-11-04-dbus-snapshot/live-call.json).
Legend: **[V]** = verified on this machine. **[I]** = inferred, not tested.

**Bottom line:** the real `desktop-calls service` runs zbus on the GLib main context through a custom zbus 6 runtime, with no async runtime of its own. The Simulated Phone answers with the Pixel's captured introspection XML, and the scenario suite (5 scenarios, 2 harness tests) runs in about 0.1 s with two copies in parallel.

## 1. zbus 6 on the GLib main context

- zbus 6.2.1 (2026-10-16) added `connection::Builder::runtime(impl zbus::runtime::traits::Runtime)`. `crates/desktop-calls/src/glib_runtime.rs` implements it on `glib::MainContext`: `spawn` is `MainContext::spawn`, `sleep` is `glib::timeout_future`, and socket readiness is a one-shot `glib_unix::fd_source_new` watch armed only after an operation returns `WouldBlock`. **[V]** The app builds zbus with `default-features = false` and no runtime feature, so zbus starts no threads.
- zbus 6 merged zvariant into `zbus` (`zbus::{OwnedVariant, OwnedObjectPath, Str, Structure}`), removed the blocking API (`zbus::block_on` exists with `default-rt`), and defers builder errors to `build()`. serde is at `zbus::export::serde`.
- Threads in the running service: `desktop-calls` and `gmain`. **[V]** (`/proc/<pid>/task/*/comm`.) `gmain` is GLib's worker thread, which GLib starts to deliver Unix signals to `glib_unix::signal_future` (the clean stop on `SIGTERM`); none of the app's code runs on it. **[I]** GTK starts the same thread anyway once the UI lands.
- `glib-unix` 0.22 fails to compile with `default-features = false`, because `signal_future_with_priority` needs its `futures` feature. Use its defaults.

## 2. Real Pixel shapes the Simulated Phone reproduces

- `Introspect` on `/org/pipewire/Telephony` and on `agN` answers with the XML captured from the real service, verbatim, in `crates/simulated-phone/introspection/`. Neither lists child nodes. **[V]** (snapshot)
- `GetModems` and `GetCalls` return `a{oa{sv}}` (a dict), not oFono's `a(oa{sv})`. `GetModems` gives each AudioGateway an empty property list. **[V]** (snapshot)
- `GetManagedObjects` on the manager carries `AudioGateway1` and `AudioGatewayTransport1` only. `org.ofono.VoiceCallManager` appears in `Introspect` alone. **[V]** (snapshot)
- Unverified: whether real `InterfacesAdded` and `InterfacesRemoved` name exactly those two interfaces. The Simulated Phone assumes they match `GetManagedObjects`. **[I]**
- The Pixel's `Device1.Class` is `5915148` and it advertises 22 UUIDs, `0000111f` (Hands-Free Audio Gateway) among them. **[V]** (snapshot)

## 3. The harness

- Each scenario gets two private `dbus-daemon` instances (both `<type>session</type>` configs; the system bus needs no system policy here), a temporary directory `desktop-calls-test-*`, and an environment cleared down to the D-Bus, XDG, `HOME` and `PATH` variables. **[V]**
- Journal hiding uses nested namespaces: `unshare --user --map-root-user --mount` mounts a tmpfs over `/run/systemd/journal`, then `unshare --user --map-user=<uid> --map-group=<gid>` returns to the real uid, so the uid the app claims in `EXTERNAL` auth matches the one the bus sees. **[V]** that the app and `busctl` reach the buses this way; **[I]** that auth would fail as mapped root. The harness wraps the app this way only when `/run/systemd/journal/socket` exists.
- CI (GitHub Actions, `archlinux:latest` container): `unshare -rm` is **refused**, and `/run/systemd/journal/socket` does not exist. **[V]** (`Probe unshare -rm` step, run 41935763721.) So the harness runs the app unwrapped there, the app finds no journal and writes its log file, and the per-test log works in CI with no namespaces. The `just test` step passed 19 of 19.
- Two copies of the suite at once: 3 of 3 rounds pass, with no directories left behind. **[V]**
- A scenario that panics keeps its directory and prints its path; the app's log is at `state/desktop-calls/desktop-calls.log`. **[V]** (`tests/harness.rs`)
