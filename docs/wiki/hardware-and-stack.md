# Hardware and stack

- 2026-11-04: The Phone is a **Google Pixel 9a** (user, grilling round 1). Pixel phones run stock Android, so Bluetooth hands-free behaviour should follow AOSP.
- 2026-11-04: The Desktop runs Omarchy (Arch) with Hyprland 0.56.2, an Intel AX201 Bluetooth adapter, BlueZ 5.87, PipeWire 1.6.9 and WirePlumber 0.5.18. The Phone is not yet paired. `bluez-obex` and `ofono` are not installed. The Omarchy quickshell handles notifications. Rust 1.98, Python 3.14 and GTK4 with gtk4-layer-shell and libadwaita are available. Source: [env inventory](../research/2026-11-04-env-inventory.md).
- 2026-11-04: The user's `~/.config/wireplumber/wireplumber.conf.d/bluetooth-a2dp-autoconnect.conf` sets `bluez5.auto-connect = [ a2dp_sink a2dp_source ]`, which leaves out the hands-free role. That needs addressing before hands-free auto-connects. Same source.
- 2026-11-04 (omarchy 4.0.6-1): The bar has a StatusNotifierItem tray, but new icons go into a hover drawer unless pinned, and Passive icons are hidden. Bar plugins (`~/.config/omarchy/plugins/<id>/`) are an Omarchy-only alternative. Do Not Disturb is readable via `omarchy-shell notifications isDnd` or `~/.local/state/omarchy/notifications.json`. Notification action buttons are **not drawn**; only the `default` action fires, on click. Toasts sit top-right on the overlay layer, so the Incoming Call Banner must be its own layer-shell surface and must avoid overlapping them. Source: [omarchy shell integration](../research/2026-11-04-omarchy-shell-integration.md).
- 2026-11-04: Research confirmed that PipeWire 1.6.9's native backend already acts as the hands-free unit, and that `org.pipewire.Telephony` is live on this machine's session bus inside WirePlumber. The stack is fixed by [ADR-0002](../adr/0002-pipewire-telephony-and-obexd-are-the-only-phone-seam.md), and the language by [ADR-0003](../adr/0003-rust-gtk4.md). Source: [HFP stack research](../research/2026-11-04-hfp-stack.md).
- 2026-11-04: Known risks from that research: (1) there is no `Deactivate()`, so Handoff to the Phone needs a prototype; (2) Android sends Call audio to whichever hands-free device was activated most recently, so earbuds and the Desktop compete; (3) the API is young and has little field testing. Prior art: Foner (`AminBlg/kaller`, GPL-3.0) uses the same architecture.
- 2026-11-04: `bluez5.telephony.default-reject-sco = true` keeps Call audio on the Phone until the Desktop calls `Activate()`. That matches the decision that Audio Location follows the answering device ([product-shape](product-shape.md)).
- 2026-11-04: Hands-free config applied (user-approved). `~/.config/wireplumber/wireplumber.conf.d/bluetooth-a2dp-autoconnect.conf` now sets `bluez5.auto-connect = [ a2dp_sink a2dp_source hfp_hf ]` (backup in a temporary scratchpad directory). The new `~/.config/wireplumber/wireplumber.conf.d/60-desktop-calls.conf` sets `monitor.bluez.properties` to `bluez5.roles = [ a2dp_sink a2dp_source bap_sink bap_source hfp_hf hfp_ag ]` (the stock default list) and `bluez5.telephony.default-reject-sco = true`. Each property is set in exactly one file. After a WirePlumber restart, `org.pipewire.Telephony` responds and BlueZ still advertises Handsfree `0000111e`. `obex.service` (user unit, disabled) is present, and `org.bluez.obex` is D-Bus activatable on the session bus.
