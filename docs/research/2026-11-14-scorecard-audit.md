**Method, and what each label means.**

- **Read** = I opened the test or source at `32c46f0` and saw the assertion named. This is what the proof column rests on.
- **Not run** = I ran no test. That a named test passes is **inferred** from "CI passed" on the head of the PR that last touched it (`just ci-local`, which runs every job). For PR #275 the head `83da886` shows "CI passed" at 2026-11-14 11:34:17Z (checked on GitHub). GitHub's own run on `32c46f0` was still in progress when I looked, so it says nothing yet.
- A **test count** comes from `grep` over `crates/*/tests/*.rs` for `#[test]` functions followed by a `fn`: 428 in `crates/test-harness/tests` (the scenarios), 546 in `crates/core/tests`, 29 in `crates/automation/tests`. Treat them as approximate (inferred), not as what cargo reports.
- The scorecard is [`docs/wiki/polish-scorecard.md`](../wiki/polish-scorecard.md): eight numbered items and two standing targets about the Dialer. Item 5 has two halves, so it has two rows.
- Verdicts: **covered** = a named scenario, test or gallery state proves it against the Simulated Phone. **gap** = nothing proves it, or only part does. **owner-only** = only the user's Real-Phone Checklist can judge it.

## Gaps, at the top (none fixed here)

1. **Item 8, no screenshot review of the current UI.** The gallery renders every state, but no screenshot-review agent's verdict is recorded anywhere for `32c46f0`. The only review on file is the design review of 2026-11-13, made from captures of `40411a0`, before the UI pass merged. Issue #26 (the review, and where the scorecard reads its verdict) is open. Known visible defects are open too: bare numbers cut short beside a tag on the Call Pill and Call Window (#262 item 5, PR #274's findings), and gallery states that show a duration of 0:00 (#262 item 3).
2. **Item 7, no proof that "every" action is reachable.** Each surface's actions have key tests (row 7a), but nothing enumerates the user stories, and #25 (the keyboard-only suite, which fails on any action without a shown shortcut) is open. One action I found with no keyboard path at all: opening the Quiet Hours Window. The `desktop-calls` commands (read from `crates/desktop-calls/src/main.rs`) include none for it and no keybinding opens it, so only a click on the Indicator's "Quiet Hours…" entry does; `desktop-calls quiet-hours HH:MM-HH:MM` sets the same hours from a terminal (row 7b).
3. **Instrument, not an item: `just scorecard` cannot pass anything.** `crates/automation/src/scorecard.rs` returns "no evidence yet" and FAIL for every item except 3 and 5, which read a real Checklist run and never pass (5 says "scenarios not yet counted"). Its test pins `0 of 8 items pass`. Issue #27 (count the 20 scenarios, show MANUAL for items needing the real Phone) is open. So destination criterion 1 ("every item passes on the Simulated Phone") cannot be shown by the tool today.

Also seen, not a scorecard gap: GitHub's CI on `main` is not green across the window; see "GitHub CI on main" at the end.
